# 三、S4 的漏洞清单（提前防）

按"会真的毁掉结果"的严重程度排序。

## 🔴 级别 1：会让整张表变成假的

| # | 漏洞 | 症状 | 防法 |
|---|---|---|---|
| 1 | **违例的分母口径不统一** | 同一张表里有的行用 750、有的用 6000 | 在代码里显式写成常量 `N_denominator`，并在表注写明 |
| 2 | **把三个 split 混算** | train 22.7% + val 14.5% 一平均得 18.6%，但两者分布不同 | 报数一律**分 split**，禁止跨 split 平均 |
| 3 | **`γ*` 在 test 上校准** | 用测试集调参 → 测试结果乐观 | `γ*` **只能在 val 上**校准，test 只做一次性验证 |
| 4 | **Clopper–Pearson 用错样本量** | 用像素数当 n（空间强相关，严重低估方差） | n 必须是**样本数/场景数**，不是像素数 |
| 5 | **ORR 与 Harmonic 的 δ_g 不一致** | 一个用精确边界、一个用噪声边界，比较不公平 | 在表注里写清"ORR 是 oracle 上界，Harmonic 是同等噪声下的可实现最优" |

## 🟠 级别 2：会让数字偏乐观/偏悲观

| # | 漏洞 | 防法 |
|---|---|---|
| 6 | 平滑估计 `κ_MLQ` 漏掉高曲率尖峰 | 已用 `kappa_oracle = 洞内 P95` 兜底；W4 要**同时**报 `C_5pt_max` 比值（必须 ≤1） |
| 7 | 边界噪声 `δ_g` 只在 3 个场景上测过 | 在 W4 的结论里注明"δ_g 来自 3 场景探针，P95=0.13" |
| 8 | `ρ` 用了 `kappa_hat`（可观测）但标签想按 `kappa_oracle`（不可观测） | 两者**分开报**：标签用 oracle、部署用 hat，这是两套口径 |
| 9 | 认证率随 seed 波动 | 校准用**全部 val**（1500），不要抽样 |

## 🟡 级别 3：工程坑（会浪费时间）

| # | 坑 | 防法 |
|---|---|---|
| 10 | `.npz` 懒加载 vs 全加载 | 15000 × 0.86 MB，全加载约 12.9 GB；建议**按分片懒加载**，每个分片 1.6–2 GB |
| 11 | `orr` 是 float32、`kmap` 是 float16 | 读取时 `.astype(np.float64)` 再算，别在 float16 上求差 |
| 12 | `meta` 是 JSON 字符串数组 | `json.loads` 逐条解析，里面 `kappa_ps` 是 5 个分位数 |
| 13 | 分片文件名 `shard_000_000N.npz` 可能被旧任务覆盖过 | 一律以 `manifest_000.json` 里的 `sha256` 为准，进场先跑 `code/verify_w3.py` |
| 14 | Poisson/稀疏求解在 256² 上每样本 ~0.1 s | 别在循环里重复解同一个洞；用 `orr` 里已存的结果 |

# 四、W5（神经网络）交接稿要提前想好的事

新 agent 在 S4 结尾写 `交接_S4到S5` 时，**必须已经回答**下面这些，否则 S5 会卡住：

## 4.1 数据与算力

| 项 | 必须写清 |
|---|---|
| 训练数据 | `data/train` 6 个分片、12,000 样本、10.27 GB；SHA256 清单在 `manifest_000.json` |
| 验证/测试 | `data/val` 3 片 1,500、`data/test` 3 片 1,500 |
| 外部基准 | `data/sf_val` / `data/sf_test`（**待补**，缺 GT） |
| 服务器 | 规格、显存、磁盘、**数据如何传**（12.84 GB） |
| 框架 | PyTorch 版本、CUDA、是否要 `h5py`（当前 schema 是 npz，不需要） |

## 4.2 模型与损失（已有定稿，不许改结构）

```
ψ_final = h_input + M_fix · Δψ_net
M_fix = smoothstep( dist(x, ∂Ω_clean) / w_blend ),  w_blend ≈ 6 px
M_fix 定义在 Ω_roi \ Ω_clean（含降质区），不是只在盲区
```

必须交接清楚：
- `h_input` = 观测边界的调和延拓，锚在 `∂Ω_clean`（collar = 2 px）；
- 网络只学**残差**，不学绝对相位；
- `L_smooth` 只作用在 `M_fix` 内部，不许跨混合带；
- 推理时 `Ω_clean` **单帧自估**，禁用 GT mask。

## 4.3 S5 的出口门禁（必须提前写进交接）

| 门禁 | 判据 |
|---|---|
| G5-a | 总体 Ours/Biharm ≤0.95；分形状 ≤1.05×min(ORR,Biharm)（5 seeds，报 mean±std） |
| G5-b | **零样本 SynthFringe**（不重训）掉点 ≤ 20% |
| G5-c | `‖Ours − ORR‖ < ‖ORR_noisy − ORR‖`（这个不等式是 C3 的核心，必须逐样本成立率 ≥ 80%） |
| G5-d | 实参规模、训练时间、显存峰值记录在案 |

## 4.4 必须传递的"不要再踩"清单

1. `vinf` 与 `h_input` **严格同域**（`dead ⊕ collar`）；
2. 洞碰图像外框或 ROI 边界 → Class U，不发证书；
3. `orr` 必须 float32（float16 在 300 rad 处 0.25 rad 台阶）；
4. `κ` 的百分位是"类有多保守"的建模旋钮，不是常数；
5. 三套口径（`κ_oracle` / `κ_hat` / `γ*·κ_hat`）不许混用；
6. 数据生成器的几何参数已冻结，S5 **不许**为了提指标去改数据。
