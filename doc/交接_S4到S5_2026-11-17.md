### 6.2-bis 两套标签切换（γ=1 的 `cls` vs 训练用 γ=0.75）

**数据里存的是 γ=1 的 `meta["cls"]`，不是训练标签。** 当前实测（val）：P **109/1500 = 7.3%**（在 750 个含 `vinf` 样本内 14.5%）；train：P **1364/12000 = 11.4%**（在 6000 个含 `vinf` 内 22.7%）。**“P 只占 4.6%”是旧几何 / 旧 pilot 的数，已作废**，不要再引用。

训练用 γ=0.75 的标签，必须在 Dataset 里**现场重算**，不许改 npz：

```python
# m = json.loads(meta_str); gamma = 0.75; PHI_TOL = 0.314159
if m["branch"] == "degraded":
    cls = "R"
elif m.get("vinf") is None:
    cls = "U"
else:
    # certificate condition, NOT rho <= gamma:
    bound = gamma * m["kappa_hat_ps"][1] * m["vinf"] + 0.13
    cls = "P" if bound <= PHI_TOL else "U"
```

> **2026-11-17 修正**：旧稿写的 `rho = (kappa_hat*vinf+delta)/phi_tol; rho<=gamma` 是错的——它把 `delta_g` 也乘进了 `gamma`，γ=0.75 只得 P=20/1500。正确条件是上面的证书不等式，γ=0.75 得 P=193/1500，与 W4 完全一致。

- γ=1 → P 109/1500（7.3%）；γ=0.75 → P 193/1500（**12.9%**，即 750 个 `vinf` 内 25.7%）。两个标签集都能随时切；**不改数据文件**，W8 要回 γ=1 或换 ε 零成本。
- 训练辅助头用 γ=0.75 的 P 标签 + 逆频率加权 CE；`L_total = L_phase + lambda_cls * L_cls`，`lambda_cls <= 0.1`，逆频率权重**只作用于辅助头**。
- **必须单独报 P-class recall / F1（recall >= 0.5）**；在 12.9% 的 P 占比下，全预测 U 也有 87% 总体准确率，只看 accuracy 会漏掉塌缩（这是本项目第 5 次“看起来正常但是假的”风险点）。
- 推理时 Tier-1 证书与 R/P/U 由 `kappa_hat/vinf/delta_g/phi_tol` 直接算，**不依赖网络分类头**。

## 8. 给 S5 的“不要再踩”六条

1. `vinf` 与 `h_input` **严格同域**（`dead ⊕ collar`），不许退回 `dead`；
2. 洞碰图像外框或 ROI 边界 → Class U，不发证书；
3. `orr` 必须 float32 存储、float64 计算（float16 在 300 rad 处 0.25 rad 台阶）；
4. `kappa` 的百分位是“类有多保守”的建模旋钮，不是常数；P75 主、P90 敏感性；
5. 三套口径（`kappa_oracle` / `kappa_hat` / `gamma*kappa_hat`）不许混用；
6. 数据生成器的几何参数已冻结，S5 **不许**为了提指标去改数据。
