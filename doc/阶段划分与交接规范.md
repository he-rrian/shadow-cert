# 题目 2 · 阶段划分与交接规范

**版本**：v1.0（2026-11-16）｜ **适用**：本项目所有阶段
**规则**：**每进入下一阶段之前，必须先写完上一阶段的交接文件，并满足其"出口门禁"。**

---

## 一、为什么要有阶段和交接

这个项目已经出现过 3 次"看起来在前进、其实数据是废的"：
1. 级联解包的阶次 bug（残差先取模再算 k，整条链退化）；
2. `f0` 取绝对值导致相位变共轭（误差 1.5 rad）；
3. `orr` 的包围盒边界填 0（误差 20 rad，55% 假违例）。

**三次都是同一个模式**：一个底层量的口径错了，上层所有数字都"看起来正常"，直到某个交叉检验对不上。
**阶段门禁 + 交接文件的作用就是强制在每个边界上做交叉检验，而不是把错误带到下一阶段。**

## 三、交接文件规范

**文件名**：`doc/交接_S{上一阶段}_到_S{下一阶段}_{日期}.md`
**时机**：上一阶段门禁全绿（或被迫中止）时写，写完才算交接完成。

### 必含九节

| # | 章节 | 内容要求 |
|---|---|---|
| 1 | **一句话状态** | 现在在哪、能不能往下走 |
| 2 | **已完成** | 每条都带**可复现命令**和**产物路径** |
| 3 | **未完成 / 阻塞** | 具体到"哪个量、多大、和什么对不上" |
| 4 | **关键决定与理由** | 含**被否决的选项**及否决原因（防止下一个人重走弯路） |
| 5 | **关键数字** | 一张可核对的表，标注测量脚本 |
| 6 | **文件地图** | 哪些是当前有效、哪些已废弃（**废弃的必须标出来**） |
| 7 | **下一步** | 按优先级，每条带**验收判据** |
| 8 | **陷阱清单** | 踩过的坑 + 症状 + 修法（这是最值钱的一节） |
| 9 | **环境与依赖** | Python 包、数据路径、显存/磁盘需求 |

### 三条纪律

1. **废弃产物必须显式作废**（改名或删除），否则下一个人会拿旧分片当新数据；
2. **"已验证"必须写验证方式**（哪个脚本、哪条命令、输出是什么），不接受"我觉得对了"；
3. **被否决的方案要写原因**——否则会被重新提出来再试一遍。

## 四、S3 的特殊门禁：ORR∕Harmonic 自洽检验

这是本次新增的强制检验，因为 **ORR 与 Harmonic 在数学上只差一个边界噪声**：

```
给定同一个洞、同一套边界数据：
  | ORR(精确边界) 的误差 |  ≤  | Harmonic(加噪边界) 的误差 |
违反这条 → 求解器或口径有 bug，禁止进入 S4。
```

**实现**：`code/check_orr_consistency.py`（待写，15 分钟工作量）——单样本上跑三种组合：
① ORR 用精确边界；② Harmonic 用精确边界（应与 ① **完全相同**）；③ Harmonic 用加噪边界（应比 ① 略差）。
②≡① 是最强的检验：两条代码路径必须给出同一个数。
