## 指令 1（必做，约 20 分钟）：把 SynthFringe 外部基准扩到 600 个含 vinf 样本

### 为什么必须做

SF 目标域重标定（`code/w4_sf_recal.py`）的结果是：

| ε | 结果 |
|---|---|
| 0.05 | **无解**（`n_cert≥50` 且 `CP≤5%` 不存在） |
| 0.10 | **无解** |
| 0.20 | val 42.5%（CP 17.2% ✅）；**test 29.6%，违例 14.1%（CP 22.7% ❌ > 20%）** |

test 的 CP 上界 22.7% 超了 20%，**原因是样本量不足**：test 只有 71 个认证样本，CP 区间太宽。
这是把 C4 从"域内证明"升级为"跨域可信"的唯一证据，现在这个数会被审稿人直接抓住。

### 怎么做

```powershell
# SF-val 与 SF-test 都要扩（校准集与验证集必须同步扩大）
python code\w3_export_sf.py --split val  --per-family 200
python code\w3_export_sf.py --split test --per-family 200
```

- 每族 200 → 总 1,200 样本，其中 **含 `vinf` 的 600 个**（sliver/arc/blob 各 200）
- GT 已存在（blocks 12–17 共 1,018 场景），**不需要重跑级联**
- 导出后必须重跑 `code\w4_sf_recal.py` 更新曲线

### 验收判据

| # | 判据 |
|---|---|
| 1 | 各 split 含 `vinf` 样本 **≥ 600**，manifest + SHA256 齐全 |
| 2 | ε=0.20 档：SF-test 的 `n_cert ≥ 150`，且 **`CP95(A-cert) ≤ 20%`**（预期 ≈15–18%） |
| 3 | ε=0.05 / 0.10 仍无解 —— **这是真实结论，不是缺陷**，如实记录 |
| 4 | 重跑后 `w4_sf_recal.md` 更新，并在 v3.1 修订记录追加一行 |

> **注意**：若扩样后 ε=0.20 仍 CP 不合法，**不要调 γ 去凑**（那是射箭画靶）。改为在论文里如实写"该域需要 >N 个校准样本才能给出 CP 合法的 20% 证书"，并给出 N 的估计。

## 指令 3（写作约束，写进论文提纲）：C4 的措辞红线

### 红线

| ❌ 绝对不能写 | ✅ 可以写 |
|---|---|
| "我们的证书在跨域上提供覆盖率保证" | "证书本身**跨域 sound**（不误发）；`γ` 是**域相关参数**，换域须用目标域校准集**零重训重标定**" |
| "零样本达到 25% 认证率" | "MATLAB 域 25.7%/25.2%（ε=0.05）；SynthFringe 域 γ=1 下 **0/240**（sound 但无覆盖），重标定后 ε=0.20 达 29.6%" |
| "证书是 distribution-free 的" | "**Oracle-κ 定理**是 distribution-free（条件于 κ 类）；**部署级 κ̂ 证书**依赖域内校准" |

1. **SF γ=1：0/240**（sound 但零覆盖 —— 这是"证书从不误发"的最强证据）
2. **SF 重标定 ε=0.20：29.6%，CP 22.7%**（指令 1 后更新为新值）
3. **MATLAB 主口径 ε=0.05：25.7%/25.2%，CP 3.23%/4.05%**

这是全篇**唯一一处**「理论成立但工程上不可跨域直接使用」的地方。主动写清 = 严谨；被审稿人问出来 = 致命。
