## 0. 叙述口径（2026-11-20 锁定）

- **不要写“接受率 0%”**；写 **“refusal correctness 11/11”**。
- 11/11 U 不是系统失败，而是 **C1 证书的正面证据**：真实遮挡的 `vinf` 在 88–654，合成 P 类小内孔只有 ~10–20；`rho` 2.5–44，**边际很大，不是临界值**。这是 **Theorem 6（2π 活塞不可观测）在真实数据上的体现**：大面积/贴边阴影本来就不在可证明恢复的类里。
- 对 γ/κ̂ 域迁移免疫：ρ 远离 1，审稿人不能用“跨域标定不对”解释这个 0/11。
- G7 的护栏按设计工作：`n_P≥5` 防止“全拒系统混过 G7”；现在 **n_P=0 → G7 = insufficient**（不是 pass，也不是 fail）。
- S7 真实部分按三段写：
  1. **拒绝行为验证**：11/11 真实遮挡被 C1 正确拒绝；引用 W8 U 类经验失败率 10–19%，说明“如果硬恢复，错误率就是这个量级”——拒绝避免了什么。
  2. **定性 + 点误差表**：6 个 GT 可用场景（scene_01/04/05、Train、实测2、实验4），描述性，不挂门禁。
  3. **Limitations**：真实数据集不含 P 类小遮挡（vinf ~10–20 量级），G7 因 n_P=0 无法计算；未来工作 = 采集带小孔遮挡的真实场景。这句 limitation 同时是下篇文章的钩子。

**问题**：真实场景在推理前，C1 证书能不能发出 P（可证明）？这决定 G7 有没有 P 场景可评。C1 是模型无关的：只用单帧 frontend 的 Ω_roi / Ω_d、`vinf`、部署 κ̂，不跑网络、不用 GT。

**口径**：
```
rho = (gamma * kappa_hat * vinf + delta_g) / phi_tol
P if rho <= 1 and dead 不触 ROI/图像边界
U otherwise
gamma=0.75, delta_g=0.13, phi_tol=pi/10, kappa_hat = fixed-kernel P75 on delta_g collar of phi_obs
```
ROI 用 `w9_roi.estimate_roi`（单帧调制度+轮廓连续性）；dead 用 `frontend` 的单帧估计。

## 3. 对 G7 / N_eff：**refusal correctness 11/11**，n_P=0

- **拒绝正确性 11/11**：C1 对 11 个真实遮挡全部判 U；这不是“接受率 0%”，而是“该拒的都拒了”。
- **n_P = 0**（11/11 U）。
- 按用户锁定的 G7 护栏：`n_P ≥ 5`；**n_P=0 → G7 = insufficient**，不是 fail，也不是 pass。
- “全拒”系统**不能**靠 handled=11 混过 G7；这正是 n_P≥5 护栏要防的；门禁设计被真实数据验证了一次。
- 真实数据在 C1 层就全部被拒，**不需要跑网络来算 G7 的像素失败率**；G7 的瓶颈不是 GT、也不是 C4 λ，而是 **真实场景没有 P**。
- 论文写法：**refusal correctness 11/11（P=0/11）**；这是 C1 条件证书的正面结果，不是模型失败。P 类在合成里是“小内孔”（0.8–3.5%/洞，内闭），真实遮挡是“大/贴边阴影”，两者不在同一类。
- 引用 W8 的 U 类经验失败率 **10–19%**：这些场景如果硬恢复，错误率就是这个量级；拒绝避免了什么，一目了然。

## 4. 限制与下一步

- 本结果依赖单帧 frontend 的 ROI/dead 估计；GT-badmask 诊断已排除“只是 ROI 估坏”的主因（6/6 仍 U）。
- `vinf` 是 ROI 尺寸/形状量；真实 700²/595² 比合成 256² 大，但即使按尺寸归一，真实遮挡的形状（大 blob/贴边）仍给出高 vinf。
- 下一步不是“调 γ 让真实变 P”（那是 test tuning），而是：
  1. 接受 **G7 insufficient（n_P=0）**，写进 Limitations；
  2. 真实场景只做 **定性/点误差**（scene_01/04/05、Train、实测2、实验4 的 GT 可用；实测1/实验3/scene_02/03/06 只定性）；
  3. 若审稿人要求“真实也有 P”，只能改采集协议（更小的内闭遮挡），不能在现有 11 场景上重划。
- W10 三项重训不受影响，继续跑。
